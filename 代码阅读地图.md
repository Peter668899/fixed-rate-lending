## 四、读代码的四个抓手（新手最快上手的方法）

1. **先看修饰符，再看函数体**  
   函数签名上一串修饰符就是"门禁"。比如 `depositLend(...) nonReentrant notPause timeBefore(_pid) stateMatch(_pid)`，  
   意思是：防重入 + 未暂停 + 在撮合期前 + 池子处于撮合期。四条都过才轮到函数体执行。  
   业务约束全写在门禁里，比读十行 if 判断更高效。
2. **认准"份额三行套路"**  
   全合约重复 6 次：
   ```solidity
   uint256 userShare = 我的量.mul(1e18).div(总量);      // 我占多少比例
   uint256 结果 = 可分配总量.mul(userShare).div(1e18);  // 按比例分给我
   _redeem(msg.sender, token, 结果);                   // 真正转钱
   ```
   看懂它，`refundLend` / `claimLend` / `refundBorrow` / `claimBorrow` 四个函数就自动看懂了。
3. **盯住两个"动钱"函数**
   - `getPayableAmount(...)` = 收钱（钱离开用户钱包的唯一时刻）
   - `_redeem(...)` = 付钱（钱离开合约的唯一时刻）  
     任何资金流向问题，都能顺着这两个函数查清楚。
4. **状态机是第一性原理**  
   池子五种状态决定了一切函数能不能调用。遇到"这个函数为什么报错"，先查池子当前状态。

## 六、注意事项（重要）

- **注释是后加的，代码一行没改**。全部 24 个文件已用"去注释后逐行比对"的方式校验：代码逻辑与原始版本 100% 一致。
- 原始未注释版本已备份为 `pledge-study/backup/pledgev2-原始未注释副本-20261004.tar.gz`，需要时可还原。
- 本项目**未安装依赖**（无 node_modules），所以没有做编译验证；由于代码行完全一致，编译结果必然与原始版本相同。
- 代码里有若干**值得向负责人确认的点**，已在注释中用 ⚠️ 标出，例如：
  - `liquidate()` 缺少 `finish()` 那样的滑点保护（行情暴跌时贷款人可能拿不回全额本息）
  - `_swap()` 里对 DEX 授权了"无限额度"（`uint256(-1)`）
  - `DepositLend` 事件的参数名叫 `mintAmount`，但实际并没有铸币
  - `minAmount = 100e18` 隐含"代币必须是 18 位小数"的假设
  - `BscPledgeOracle.setPrices()` 用循环下标当 key，与按地址取值的口径不一致
  - `multiSignatureClient.checkMultiSignature()` 的防重放逻辑被注释掉了
  - `AddressPrivileges.getMinter()` 在集合为空时存在下溢风险
